# Integration handoff

Only the sole Git integrator applies these files. Formal port 8766 and runtime/design checkouts remain unchanged by this delivery.

1. Copy portable directory to `tools/ai/` in the target checkout (exclude test scratch/state). `plugin.json` at that directory remains a standalone plugin root. Copy `web/ai-panel.js`, `web/integrated.js` and `web/ai-panel.css` to production `web/ai/`. Do not replace production index/app/native assets with the sidecar page.
2. Apply the matching exact server hook patch in the delivery `integration/`: `server-phase3.patch` is based on the backend owner's phase3 portable server; `server-c17c525.patch` is the phase2 alternative. Apply one, never both. Both only add optional AI routing.
3. Add `ai_client_config` to the trusted local gateway configuration, pointing to the reviewed local client config. Set its gateway_url to the actual gateway port. It must use a durable own state_dir. No secrets or site configuration enter browser/model arguments.
4. Apply `integration/ui-index.patch` (two additive references only). `web/ai/integrated.js` imports the actual UI app module and consumes its published, immutable `window.ICWorkbenchContext` API v1 (`getContext`, `subscribe`, `readSelection`), then inserts its own `#ai-panel` after `.results-panel`. The public API was verified in the UI owner phase4-context portable code on 2026-11-09. The package intentionally does not patch UI closure internals. Hooks: `getContext`, `subscribe`; reserved `readSelection`. Waveform panel remains independently mounted.
5. Gateway shutdown must call `app.ai.session.close()` when the optional service exists. Before production restart, run isolated tests and review exact patch against the current owner snapshot.

The bridge makes an ordinary official local app-server child, starts an ephemeral read-only scratch thread, requires effective `approvalPolicy != never` and `approvalsReviewer == user`, and inherits normal model/provider unchanged. `allowProviderModelFallback:false` prevents fallback. Shell/native editing and unrelated connectors are disabled for this thread. This does not edit global Codex config or approval settings. The installed binary's ordinary auth APIs determine availability; no auth-file inspection is implemented.

Sidecar browser proof is a real model interaction with the formal gateway, but it is not proof that the production native UI has mounted the component. The actual UI owner phase4-context code was copied into an isolated gateway on 8769: mountCount=1, context version=1, dirty draft blocked before turn, browser errors=[]. Native geometry fidelity/production deployment acceptance remains with its owners. No claim is made about native geometry regeneration, terminal current resolution, or remote simulation cancellation.
