# Installation and removal

No global configuration, authentication file or installed plugin was changed during validation. Do not copy runtime evidence, state or site files into the distributable plugin.

## Dry run (zero installation)

1. Copy `config.example.json` to an owned local path; configure existing loopback gateway and a durable state directory. `python3 -B ic_workbench.py --json schema` works offline.
2. Start `python3 -B ic_workbench.py --config /path/client.json mcp` with an MCP client. Initialize JSON-RPC, notify `notifications/initialized`, then `tools/list` / `tools/call`. stdout contains MCP only. All mutation tools prepare requests; no approve tool exists.
3. For a Codex-native proof without installing, start an ephemeral app-server thread with a per-thread `config.mcp_servers.ic_workbench` command array. Call `mcpServer/tool/call` with `server:'ic_workbench',tool:'ic_read',threadId,arguments`. Do not edit global config. The delivery includes an actual trace from this path.

## Local plugin install (explicit user action)

First run `python3 -B tools/dev/build.py codex` from the repository root. Copy the resulting `dist/ic-workbench/` directory under a dedicated local marketplace root, e.g. `plugins/ic-workbench`. Create that marketplace's `.agents/plugins/marketplace.json` using:

```json
{"name":"local-circuits","plugins":[{"name":"ic-workbench","source":{"source":"local","path":"./plugins/ic-workbench"},"policy":{"installation":"AVAILABLE","authentication":"ON_INSTALL"},"category":"Productivity"}]}
```

Supported local CLI commands, verified with the installed help:

```bash
codex plugin marketplace add /absolute/local-marketplace-root
codex plugin add ic-workbench@local-circuits
```

The MCP command in `mcp.json` reads `${PLUGIN_DATA}/config.json`, a user-owned persistent plugin data file. Place the reviewed local gateway configuration there using the host-reported plugin data location. Do not guess this location or edit the plugin cache. If the current host does not supply `PLUGIN_DATA`, use the explicit standalone MCP configuration below until the host supports the portable variable. No automatic setup hook creates files or modifies user settings.

Alternatively add an explicit MCP configuration using the official CLI:

```bash
codex mcp add ic-workbench -- python3 -B /absolute/portable/ic_workbench.py --config /absolute/client.json mcp
```

This command changes user configuration and was **not** executed in this task. Both forms use the same Service. In desktop, use the local marketplace's plugin entry to install/enable, then invoke the IC Workbench Skill. Configuring the gateway is required before MCP tools start successfully; missing config is a real failure, not a mock fallback.

## Uninstall (explicit user action)

```bash
codex plugin remove ic-workbench@local-circuits
codex plugin marketplace remove local-circuits
# Only if the standalone MCP entry was installed:
codex mcp remove ic-workbench
```

Preserve state/receipts for uncertain or submitted jobs; removal does not cancel remote runs or delete published results. Do not delete state until all pending operations are reconciled.
