# Circuit libraries

Use **电路库** in the online workbench to select a library, cell and view. Search by cell or library name. Native schematics open in the existing RNL viewer; documentation and configuration views open as read-only text. A view records its exported display level so the viewer does not start on an empty assembly root.

The library layout follows `lib/<library>/<cell>/<view>/...`. `lib/catalog.json` lists the libraries, each `library.json` lists its cells, and each cell has a README and explicit view file inventories. `schematic/` and `symbol/` preserve the recorded geometry and dependency paths. Documentation explains the original library/cell identity, included source hashes, transformations, unresolved models and simulation status.

The public catalog contains 97 cells. Identical imported sources and common RNL support files have a single physical owner. A view's `aliases` map reconstructs its relative include/package paths from those declared files; aliases are virtual names, not separately editable copies. Edit an owned physical file through its owning cell, and refresh/check all affected views. Historical provenance and original import hashes remain unchanged by that storage layout.

Opening an ADC schematic clears the RC analytical waveform and simulation state. Use the RC reference entry to return to that example. The AI connection settings offer **使用当前电路** to bind the next conversation turn to the local library identity; running turns prevent rebinding. A cell with `project_id: null` remains unbound to a simulation project. A manifest binding alone does not prove that the connected runtime has that project, models or licenses.

## Add or reproduce data

1. Add the cell under its library with a README and the complete view dependency set.
2. Declare the cell and views in `library.json`. Paths must be repository-relative and explicit. An RNL view may have a `level` containing the exact exported display level. Do not replace missing geometry with automatic wiring while describing it as an original schematic.
3. Preserve attribution and source/transformation evidence. Keep model cards, external standard-cell implementations, site settings, credentials, runtime state and unreviewed results outside the publication inventory.
4. Validate and build:

```bash
python3 -B tools/dev/build_library.py
python3 -B tests/library/test_build_library.py
python3 -B tools/dev/build_pages.py
```

The static build copies only indexed assets into `site/library-files/`. It rejects symlinks, path traversal, unsupported file types, private machine paths and common credential patterns, and limits both individual files and total export size. Those checks supplement the recorded data review; they do not determine ownership or redistribution rights.

`tools/library/import_adc.py` reproduces the reviewed ADC migration from its pinned source export. Its input is the original engineering checkout, supplied explicitly as `--seed-root`; the public clone does not contain that private checkout. `--check` verifies the generated bytes against the same reviewed import plan. New data needs its own reviewed inventory rather than a wildcard copy.

## Cell version workflow

Open **版本**, then select the library and cell in **电路库**. The version panel follows that selection independently of the AI project. Its **文件 / 历史 / 提交–PR / Testbench CI** tabs show circuit data; application release commits are excluded.

The public website displays the published source and cell-scoped Git history without a connection. Editing requires a local connection helper started from a Git checkout of this repository with its GitHub `origin`; a ZIP download still supports chat and viewing, but has no Git history or branch to edit. GitHub PR operations also require the helper's existing `gh` login with access to that repository. The site never collects a GitHub token. If the local checkout differs from the published snapshot, inspect its identity and choose **使用本机版本** before editing.

1. In **文件**, choose an owned source or configuration file, edit it and inspect the diff. A paired direct library save uses the existing local authorization without another approval window. Each successful save records both the previous and new bytes in a local checkpoint before replacing the file. Shared dependencies and import provenance remain read-only from that cell.
2. In **历史**, inspect cell-only commits and local file checkpoints. Restore the chosen file from a commit, or from either side of a checkpoint. Restoration writes a new working change and checkpoint; it never resets the branch or removes later commits.
3. In **提交 / PR**, review the current cell diff and edit the suggested title and description. The initial suggestion is a deterministic description of changed files, not a model-generated claim about circuit behavior. Commit records only the cell's approved paths and preserves unrelated staged changes. It does not push automatically.
4. **创建 PR / 更新 PR** shows the exact branch, base and commit. The explicit action uses the paired authorization to push that commit without force and create or update the PR. Its whole diff must belong to the selected cell. It never merges the PR. **刷新 PR 状态** performs one explicit read of GitHub check results.
5. In **Testbench CI**, choose registered TBs and save the cell's `ci.json`. Commit that file with the circuit and publish the PR to trigger the configured checks. See [TB CI](circuit-ci.md) for source checks and the separately configured, licensed Spectre workflow.

Library Agent tools use the same configured checkout and durable ledger when `library_access: direct` is enabled; default or explicitly selected read-only access still forbids writes. These finite library operations do not change remote simulation authorization. An uncertain, partial or rolled-back result stops dependent actions until the original receipt is checked; reconnecting does not resend it or create a new key. See [Agent library tools](library-agents.md).

Checkpoints and operation receipts live under the helper's ignored `.local/` state. They are not uploaded by Git commits. GitHub retains committed cell versions, PR discussions and CI reports. Edits made by an external editor appear in the current diff, but CircuitGit does not claim to capture every intermediate external write. Imported ADC snapshots start with their real import commit; private historical revisions are not fabricated.

**查看本机原理图** opens the allowlisted current RNL source closure in the existing viewer, marked as a local snapshot. Saving an electrical netlist alone does not regenerate Virtuoso placement/wiring; exported geometry, circuit source and simulation source identities must remain explicit.

## Electrical projects and external tools

The gateway accepts explicitly registered electrical sources under either `projects/` or `lib/`. Optional `library_id` and `cell_id` describe the project; they do not authorize execution or register a snapshot automatically. Runtime requests continue to use the project, source commit, configuration and operation receipt.

The real testbench `lib/pipetisar-real/TB_PIPE_RS9_N06` is bound in the library manifest and `config/workbench.projects.json` to `pipetisar-real-TB_PIPE_RS9_N06`, with `PIPE_LOW` and `PIPE_NYQUIST` input compilation configurations. Their `simulation/source-bindings.json` describes which canonical electrical sources feed the compiled input. The connected gateway must actually load those registrations before they become selectable runtime configurations.

Save and commit the intended circuit/configuration changes before requesting simulation, then use that library's exact HEAD. When the operator configures `source_repository`, the compiler reads the selected Git snapshot directly and leaves the runtime checkout untouched. RNL and source checks for the 97-cell catalog, and compilation of these two ADC configurations, do not require local PDK or Virtuoso. Actual Spectre execution requires the exact registered external model aliases/hashes and licensed remote tools; missing dependencies are explicit blockers. Passing source CI or producing compiled input does not establish a new run or a measured result.

SpiceOwl is maintained in [its own repository](https://github.com/spiceowl-dev/spiceowl). Its optional library-context consumer is pinned at [`ebb82da`](https://github.com/spiceowl-dev/spiceowl/blob/ebb82da400b02020a4f278d08f366aad358515bb/docs/circuitgit-integration.md), currently proposed in [PR #6](https://github.com/spiceowl-dev/spiceowl/pull/6). CircuitGit keeps its existing supervision wire format for compatibility; adding project metadata alone does not send new run fields to old consumers. Library labels are optional metadata; saved run/source identity must not be inferred from whichever schematic is currently open. No SpiceOwl core is copied into CircuitGit, and no installed MCP process is automatically updated by this release.
