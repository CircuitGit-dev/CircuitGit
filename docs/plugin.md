# IC Workbench 本地插件

安装后直接在 Codex 中使用，无需在 Terminal 启动 Python。插件会启动自己的 MCP 进程；第一次调用项目功能时，复用已经运行的本地工作台，或按安装时的项目配置启动自带后端。

## 日常使用

1. 在 Codex 的 Plugins 中启用 **IC Workbench**。
2. 说“打开 IC Workbench，列出我的电路项目”。
3. 选择项目，要求打开“可排列工作台”。原理图、波形和仿真面板可拖动分屏、合并标签、关闭和恢复；原有独立窗口也保留。见 [工作台操作](docking-workbench.md)。
4. 在仿真窗口编辑配置并预览。保存、提交、收集和发布会先生成具体请求；点击 **在 Codex 中审核**，在宿主确认表单中批准或取消。

已有 Python 仍是插件内部运行环境，插件负责调用它。用户不必输入命令。模型对话使用 Codex 本身，不启动网页 AI 模型。

原理图保留已导出的元件位置、符号和走线。波形窗口读取指定运行的真实结果；节点联动仍需核验来源与端口。程序启动不等于运行仿真，确认提交也不等于仿真完成。

## 连接与故障

“检查 IC Workbench 状态”会返回已配置项目和连接情况。插件启动入口不会因为网关未运行而丢失工具目录。配置缺失、端口被其他服务占用或启动失败时，会明确说明并停止依赖操作；不会改端口、杀掉其他进程或自动重复提交。

服务由多个 Codex 会话共用，关闭某个窗口或会话不会终止仿真和其它窗口使用的网关。插件不会自动关闭已有网页服务。

若宿主不支持人工确认、权限策略拒绝确认，或确认超时，请求继续保留。不要让模型替你确认或改成自动审批。当前聊天没有加载新插件工具时，保存工作后重新进入会话；必要时重启桌面应用。

## 开发与安装

源码在 `apps/codex/`，后台复用 `tools/workbench/` 的固定执行器，构建时复制到插件的 `gateway/`。已有工程、站点配置、许可证与结果留在原来的位置。

开发者运行 `tools/dev/build.py all` 和 `tools/dev/marketplace.py` 得到完整本地插件目录；用户安装不必亲自运行这些脚本。协调助手可完成本地 marketplace 注册、安装和项目配置。

可分发包中的 `mcp.json` 使用宿主的 `PLUGIN_ROOT`、`PLUGIN_DATA`。本站安装器将项目配置的绝对位置写入生成的本机 marketplace 启动参数，配置内容放在被 Git 忽略的 `config/codex-plugin.local.json`，不会把凭据复制到插件包。旧的直接 MCP 连接在插件安装成功后移除，避免重复工具。

桌面宿主是否实际展示窗口需单独验证。插件已安装、MCP 协议通过、界面测试宿主通过，均不应被写成未经观察的原生窗口已显示。

安装器必须通过 Codex 自身的 MCP 服务发现，并使用宿主解析后的启动参数核验安装缓存。`mcp.json` 中的 `command` 保持 `python3`；portable MCP 不允许把本机 Python 的绝对路径写入该字段。运行时只需要 Python 3.9 及标准库。已有安装可由助手使用安装器的 `--upgrade` 更新，保留原有项目配置和审批策略。
