# Dockview Studio

The independent Studio entry is `/studio/dockview/index.html`. It uses Dockview for tab groups, splits, floating panels, close/reopen, maximize and local layout persistence. The original Studio entry and Codex plugin remain available. This is a browser-hosted workbench prototype; it is not yet a packaged desktop application.

The implementation mounts the existing RNL viewer, simulation configuration, AI sessions and waveform component into four panel slots. Closing parks the mounted component in a hidden connected container, retaining drafts and loaded curves. It does not cancel a model turn or simulator job. Tab visibility is propagated to AI polling. Reloading restores layout, including an all-closed layout; in-memory circuit/waveform drafts do not acquire cross-reload persistence merely by saving the layout.

The Window selector restores panels. Each group offers float and maximize actions. A floating group's arrow changes to “放回主布局” and docks that group back; the Window menu also has “收回所有浮动面板”, including when no docked groups remain. Drag the tab itself (not the empty floating title-bar space) to another group's tabs to combine, or to an edge to split. Floating groups stay inside the workbench; operating-system popout windows are not enabled in this prototype because the existing RNL renderer has document globals.

Floating records the original grid, neighbours, tab order and size. Returning replays the exact original layout only if all other placement and size information is unchanged. Otherwise it uses the surviving neighbours and original proportions, preserving newer panel closures and edits. Dock homes and last floating rectangles are stored alongside the layout, so they survive reload. Existing floating panels created before this feature have no prior home: dock and float them once to establish it.

Plot commands use the docked waveform panel in this entry. Existing source/run/geometry mapping checks are retained. Esc exits probe mode. No browser popup is created. The waveform surface contains only a selected-trace list and a canvas. F fits the time range; Z followed by dragging zooms a time segment; Shift+Z or minus zooms out; arrows and dragging pan; A/B chooses a cursor to place by clicking. L opens the saved-signal picker, M opens measurements and source/run details, and ? opens shortcut help. These are this application's bindings, not a promise to match a particular Cadence bindkey file. Read errors appear in the shared application status line. Run identity, provenance and freshness remain available in M; simplifying presentation does not loosen probe validation.

Canvas dimensions follow the actual panel bounds and device pixel ratio. Resizing, docking and tab activation redraw retained data; fixed minimum backing-store dimensions are not used. Keyboard events inside the waveform surface do not reach the schematic's page-level handlers.

Dragging and wheel zoom redraw the retained curves on animation frames. The canvas backing store changes only when its dimensions change. Display samples are reduced to time-ordered min/max pairs per screen column, preserving narrow peaks in the supplied data. A retained full-range overview fills in while detail arrives. Live window reads are coalesced, with at least 180 ms between interactive batches and only one batch in flight; release requests the final window. Slow reads or read errors do not erase existing curves. Preview measurements are withheld until the final response, and every read still passes through the adapter's run/revision checks; display sampling never supplies cursor measurements. A time range outside saved data is labelled instead of inventing values. Dockview forwards one resize notification per frame only when the schematic's dimensions actually change.

The waveform sidebar's “打开运行…” / “切换运行…” button, or O with waveform focus, opens a current-project run picker. It reads the existing job list and selects an explicit run through the Studio context. Opening plots the available exported signals (up to the existing 16-trace limit). It does not submit, collect or simulate a job. Run data without readable exports remains explicitly unavailable.

The read-only preview has no AI inference connection. The full web adapter calls `/api/ai/*` on the local Python gateway. Its AI bridge talks JSON-RPC over stdio to `codex app-server`, creates its own ephemeral thread, and supplies controlled project actions through `dynamicTools`. The Codex MCP plugin is a separate adapter over the same project service. The web bridge does not send messages into the user's current native Codex conversation or require MCP to carry its chat stream.

Help → AI / MCP 连接 describes the current chat route and provides explicitly configured stdio launch data in MCP JSON or Codex TOML. It never labels a generated configuration as a connected agent. The optional official-SDK server and future chat adapter boundary are described in [Agent connections](agent-connections.md).

`apps/web/vendor/dockview` pins the MIT-licensed `dockview-core` 4.13.1 npm bundle, with its upstream license and npm integrity record. Builds remain offline. The source map reference is removed because the source map is not shipped.

Validation: `tests/studio/dockview-browser.mjs` serves built assets and proxies only allowed reads of the existing local gateway. AI data is explicitly a fixture; the test makes no model turns or solver submissions. It checks real waveform samples, physical drag, floating, renderer preservation, unfinished simulation JSON, and all-closed layout restore. `--serve` keeps this read-only preview open; it is not a production API gateway.

`tests/waveforms/interaction-browser.mjs` uses delayed synthetic responses to verify updates before pointer release, retained curves, bounded requests, cursor freshness, run switching, cancellation and disposal. `tests/studio/dockview-performance.mjs` verifies all six real saved curves remain drawn during pan/zoom, with zero canvas reallocations during pan and bounded resize events; its frame timings describe the test machine, not a guaranteed frame rate on every client.

Production use should serve the built entry through the existing authenticated gateway. A later desktop shell can host this same UI and backend adapters; MCP remains an agent interface rather than the owner of the window layout.
