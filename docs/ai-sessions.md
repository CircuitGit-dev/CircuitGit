# AI 会话、模型和执行进度

工作台底部可以保存最多 8 个独立 AI 对话。使用会话栏新建、切换或重命名；所有会话共享当前项目源码，但各自保存消息、所选模型、回合状态、事件和审批。切换或隐藏面板不会停止正在执行的回合。

## 模型与输入

输入框旁的模型目录来自实际 app-server `model/list`，保留返回的名称和顺序。目录本身不能证明账号具有调用权限。首次显示一个会话时才读取它的目录，新建会话只保存元数据。

“跟随默认”使用该会话最初的模型。选择其他模型后再切回默认，服务端会明确恢复原模型，避免沿用上一回合的覆盖值。运行期间不能更换模型。不修改全局模型、provider 或登录配置；目录读取失败时仍可使用原默认路径。

Enter 发送，Shift+Enter 换行；中文输入法选词阶段的 Enter 不发送。

## 进度与审批

发送后立即显示等待状态和计时。执行过程默认折叠，展开后可查看已收到的工具、修改和状态事件。页面不展示原始私有推理文本。模型正文和执行诊断分开显示；Window → AI执行详情可打开诊断窗口。

后台会话的运行和待批准状态显示在会话标签上。审批只在所属会话处理；切换或隐藏会话会关闭它的对话框，不会自动批准、拒绝或取消请求。不同会话仍须通过同一源码版本校验；其他会话提交源码后，旧上下文的审批可能失效。

## 恢复与传输

会话历史保存在配置的本地状态目录，独立于电路 Git 源码。刷新页面可恢复已保存的文本。服务重启后，已完成会话的下一条明确用户消息会建立新线程，并附带有界的本会话历史参考（最多 24 条消息、24,000 字符）；工具调用与审批不会重放。历史参考不能替代重新读取当前源码。

重启时仍在执行的会话恢复为暂停；旧审批不可再次操作。保留这些记录供核对，使用新会话开始后续工作。界面不自动删除或淘汰旧会话。

各面板使用短 HTTP 轮询，每个会话最多一个在途事件请求，收到响应后约 1.2 秒再请求。隐藏会话保留轮询，避免 8 个持久 SSE 连接占满浏览器的同源 HTTP/1.x 连接。旧单会话 SSE 接口继续兼容。

## Window 菜单

AI 的显示、聚焦和执行详情由同一会话管理器处理。波形窗口入口复用已有窗口并聚焦；关闭后可以重新打开。“恢复默认布局”恢复面板尺寸和显隐，保留输入草稿及面板实例。

## 运维和验证边界

后端关闭调用 `AiRoutes.close()`，清理所有已创建的会话。部署前应检查全部会话的活动状态和未解决审批；有活动回合、未解决审批或状态不明时保留待发布版本，不停止当前服务。

本次验证使用模拟 RPC 和隔离 HTTP 会话，并保留实际模型目录的元数据证据。它验证协议、界面和恢复行为，不代表新模型推理、Spectre 仿真或电路性能验证。

接口细节以同次交付的 `session-contract.md` 为准。项目操作说明从 `tools/ai/prompts/workbench.md` 读入实际 `thread/start` 的 `developerInstructions`；其中的流程说明不会增加工具权限。
